# PRD: ระบบจำแนกเศษผ้าเพื่อนำไปรีไซเคิล (FabricSort)

Sep 25, 2026 · @Natthaphat

## ภาพรวมและปัญหา

FabricSort คือโปรแกรมที่รับรูปเศษผ้า 1 รูป แล้วบอกว่าเป็น Cotton, Polyester, Silk หรือ Viscose พร้อมค่าความมั่นใจ เพื่อช่วยคัดแยกก่อนส่งรีไซเคิล

ผ้าแต่ละชนิดต้องผ่านกระบวนการรีไซเคิลต่างกัน แต่ปัจจุบันยังคัดแยกด้วยคนเป็นหลัก ซึ่งช้า ใช้แรงงานมาก และผิดพลาดได้เมื่อผ้ามีสีหรือผิวคล้ายกัน

โปรเจ็คนี้เป็นงานวิชา Applied Machine Learning ประกอบด้วย 2 ส่วน คือ notebook (.ipynb) สำหรับพัฒนาและเปรียบเทียบ 3 โมเดล และแอป Streamlit ที่ใช้โมเดลที่ดีที่สุด

## เป้าหมายและตัวชี้วัดความสำเร็จ

เป้าหมายหลักคือได้โมเดลที่มี Macro-F1 บนชุด Test อย่างน้อย 0.85 และแอปที่จำแนกรูปได้ภายใน 1 วินาที

**เป้าหมาย**

1. พัฒนาโมเดล 3 ตัวตามแนวทางงานวิจัยอ้างอิง และเปรียบเทียบบนชุด Test เดียวกัน
2. เลือกโมเดลที่ดีที่สุดด้วยเกณฑ์ที่กำหนดไว้ล่วงหน้า
3. สร้างแอป Streamlit ให้อัปโหลดรูปแล้วได้ผลทันที
4. ส่งงานเป็น notebook ที่กด Run All แล้วทำงานครบตั้งแต่โหลดข้อมูลจนถึงเปิดแอป

**ไม่ใช่เป้าหมาย**

- ไม่จำแนกผ้าผสม (blend) หรือเกิน 4 ชนิด
- ไม่ตรวจจับผ้าหลายชิ้นในรูปเดียว (ไม่ใช่ object detection)
- ไม่เชื่อมต่อกล้องหรือสายพานจริงในโรงงาน
- ไม่ deploy ขึ้น cloud (รันบนเครื่องตัวเองเท่านั้น)

**ตัวชี้วัด**

| ตัวชี้วัด | เป้า | วัดจาก |
| --- | --- | --- |
| Macro-F1 (โมเดลที่ดีที่สุด) | ≥ 0.85 | ชุด Test |
| Accuracy | ≥ 85% | ชุด Test |
| Recall ต่ำสุดรายคลาส | ≥ 0.75 | ชุด Test (ป้องกัน Silk/Viscose ถูกละเลย) |
| เวลา inference ต่อรูป | < 1 วินาที | บน RTX 4050 |
| เวลาเทรนรวมทั้ง notebook | < 2 ชั่วโมง | บนเครื่องที่ใช้เทรน |

ตัวเลขเป้าอ้างอิงจากงานวิจัย: SVM ได้ Accuracy 94.39% (Zhu et al., 2023), ResNet50V2 ได้ F1 0.913 (Gnoupa et al., 2025) และ KNN ได้ 73.33% (Mudaffarsyah et al., 2024)

## ข้อมูล

ใช้ภาพ 4,340 ภาพจาก 2 แหล่ง 4 คลาส โดยแบ่งข้อมูลครั้งเดียวแบบ stratified และให้ทั้ง 3 โมเดลใช้ชุด Test เดียวกัน

| Class | iBUG Fabrics | TextileClass-7 | รวม | สัดส่วน |
| --- | --- | --- | --- | --- |
| Cotton | 588 | 956 | 1,544 | 35.6% |
| Polyester | 226 | 895 | 1,121 | 25.8% |
| Viscose | 37 | 892 | 929 | 21.4% |
| Silk | 50 | 696 | 746 | 17.2% |
| **รวม** | **901** | **3,439** | **4,340** | 100% |

**โครงสร้างโฟลเดอร์ที่ notebook คาดหวัง**

```
dataset/
  iBUG/{Cotton,Polyester,Silk,Viscose}/*.jpg
  TextileClass7/{Cotton,Polyester,Silk,Viscose}/*.jpg
```

**ข้อกำหนดการเตรียมข้อมูล**

1. สร้างตาราง manifest (path, class, source, sample\_id) แล้วบันทึกเป็น `manifest.csv`
2. ลบภาพเสีย ภาพซ้ำ (เทียบด้วย hash) และภาพที่เล็กกว่า 64×64 พิกเซล
3. แบ่ง Train/Val/Test = 70/15/15 แบบ stratified ตาม class และ source, seed = 42
4. **แบ่งตามชิ้นผ้า (group split)** ถ้าชิ้นเดียวกันมีหลายภาพ เช่น iBUG ที่ถ่ายชิ้นเดียวกันภายใต้แสงหลายมุม ภาพจากชิ้นเดียวกันต้องอยู่ชุดเดียวกันเสมอ
5. **Augment เฉพาะชุด Train หลังแบ่งแล้ว** (flip, rotate, color jitter เล็กน้อย, random crop) ห้าม augment ก่อนแบ่ง เพื่อไม่ให้เกิด leakage แบบที่พบในงานวิจัยหญ้าทะเล
6. จัดการข้อมูลไม่สมดุลด้วย class weight ไม่ใช้การตัดข้อมูลทิ้ง
7. บันทึกไฟล์ split (`split.csv`) เพื่อให้รันซ้ำได้ผลเดิม

## โมเดล 3 ตัวและเกณฑ์การเลือก

เปรียบเทียบ ML แบบฟีเจอร์สกัดเอง 2 ตัวกับ Deep Learning 1 ตัว แล้วเลือกตัวที่ Macro-F1 บนชุด Validation สูงสุด

|  | โมเดล 1: SVM | โมเดล 2: KNN | โมเดล 3: CNN |
| --- | --- | --- | --- |
| อิงงานวิจัย | Zhu et al. (2023) | Mudaffarsyah et al. (2024) | Gnoupa et al. (2025) |
| อินพุต | เวกเตอร์ฟีเจอร์ | เวกเตอร์ฟีเจอร์ | ภาพ 224×224 |
| ฟีเจอร์ | HSV histogram + GLCM + LBP → Chi-square/SelectKBest | ชุดเดียวกับโมเดล 1 | เรียนเองจากภาพ |
| อัลกอริทึม | SVC kernel RBF | KNeighborsClassifier | ResNet50 pretrained ImageNet, fine-tune |
| จูน | GridSearchCV: C, gamma ช่วง 0.01–100, จำนวนฟีเจอร์ k | k = 3, 5, 7, 9, 11; weights; metric | lr 1e-4, batch 32, สูงสุด 50 epoch, early stopping patience 7 |
| จัดการ imbalance | class\_weight="balanced" | ไม่มี (บันทึกเป็นข้อจำกัด) | weighted CrossEntropy |

**ฟีเจอร์ที่สกัด (โมเดล 1–2)**

- **สี:** HSV histogram (H 16 bins, S 8, V 8) รวม 32 ค่า
- **GLCM:** ภาพ grayscale 256×256 quantize เป็น 64 ระดับ, ระยะ 1 และ 2, มุม 0°/45°/90°/135° คำนวณ contrast, dissimilarity, homogeneity, energy, correlation, ASM และ entropy
- **LBP:** uniform LBP P=8, R=1 และ P=12, R=1 (ค่าที่ดีที่สุดในงาน Zhu et al.) เป็น histogram
- Scale ด้วย StandardScaler ที่ fit บนชุด Train เท่านั้น

**เกณฑ์เลือกโมเดลที่ดีที่สุด**

1. Macro-F1 บนชุด Validation สูงสุด
2. ถ้าต่างกันไม่เกิน 0.01 ให้เลือกตัวที่ inference เร็วกว่า
3. รายงานผลบนชุด Test ครั้งเดียวหลังเลือกแล้ว ไม่ใช้ Test ในการจูน

**ผลที่ต้องรายงานของทุกโมเดล:** Accuracy, Precision, Recall, F1 (macro และรายคลาส), confusion matrix, เวลาเทรน, เวลา inference ต่อรูป และผลแยกตามแหล่งข้อมูล (iBUG / TextileClass-7)

## Functional Requirements: แอป Streamlit

แอปหน้าเดียวให้อัปโหลดหรือถ่ายรูปผ้า แล้วแสดงชนิดผ้า ความมั่นใจ และคำแนะนำว่าควรตรวจซ้ำหรือไม่

**User flow**

1. เปิดแอป เห็นชื่อระบบ คำอธิบายสั้น และคำแนะนำการถ่ายรูป (ถ่ายใกล้ ผ้าเต็มเฟรม แสงสม่ำเสมอ)
2. อัปโหลดรูป (jpg/png/webp) หรือถ่ายผ่าน `st.camera_input`
3. แอปแสดงรูปที่อัปโหลดคู่กับผลทำนาย
4. ผู้ใช้เห็นชนิดผ้า ค่าความมั่นใจ และคำแนะนำการรีไซเคิลของชนิดนั้น
5. อัปโหลดรูปถัดไปได้ทันที

**ความต้องการ**

| ID | ความต้องการ | ลำดับ |
| --- | --- | --- |
| A1 | โหลดโมเดลครั้งเดียวด้วย `st.cache_resource` | Must |
| A2 | อ่าน preprocessing จาก `model_meta.json` ให้ตรงกับตอนเทรน | Must |
| A3 | แสดงคลาสที่ทำนายและ bar chart ความมั่นใจทั้ง 4 คลาส | Must |
| A4 | ถ้าความมั่นใจสูงสุด < 60% แสดงคำเตือน "ไม่แน่ใจ ควรให้คนตรวจซ้ำ" | Must |
| A5 | จัดการไฟล์ผิดประเภท/เสีย ด้วยข้อความภาษาไทย ไม่แสดง traceback | Must |
| A6 | Sidebar แสดงชื่อโมเดล, ผล Test (Accuracy, Macro-F1) และข้อจำกัด | Should |
| A7 | อัปโหลดหลายรูปพร้อมกัน แสดงเป็นตารางสรุป + ปุ่มดาวน์โหลด CSV | Should |
| A8 | ข้อความสั้นๆ ว่าผ้าชนิดนั้นรีไซเคิลอย่างไร (เช่น Polyester → recycle ด้วยวิธีทางเคมี/หลอม) | Could |
| A9 | Test-time augmentation (เฉลี่ยผลจาก flip) เพื่อเพิ่มความเสถียร | Could |

แอปรองรับรูปภาพ 1 รูปต่อผ้า 1 ชนิด และต้องไม่ส่งรูปออกนอกเครื่อง

## ความเสี่ยงและแนวทางรับมือ

ความเสี่ยงใหญ่ที่สุดคือผลที่ดูดีเกินจริงจากข้อมูลรั่ว และโมเดลใช้ไม่ได้กับรูปจริงจากมือถือ

| ความเสี่ยง | ผลกระทบ | แนวทางรับมือ |
| --- | --- | --- |
| ข้อมูลรั่ว: ภาพจากชิ้นผ้าเดียวกันอยู่ทั้ง Train และ Test | Accuracy สูงเกินจริง | Group split ตามชิ้นผ้า, augment หลังแบ่ง |
| โมเดลเรียนรู้ "แหล่งข้อมูล" แทนชนิดผ้า | ใช้กับรูปจริงไม่ได้ | รายงานผลแยกแหล่ง, ทดสอบกับรูปถ่ายเองคลาสละ 10–20 รูป |
| ข้อมูลไม่สมดุล (Silk 17%) | Silk/Viscose ถูกทายผิดบ่อย | class weight, ใช้ Macro-F1, ตั้งเป้า Recall รายคลาส ≥ 0.75 |
| คู่ Cotton–Polyester และ Silk–Viscose คล้ายกัน (งาน Gnoupa et al. พบปัญหาคล้ายกัน) | F1 ของคู่นี้ต่ำ | วิเคราะห์ confusion matrix, แสดงคำเตือนเมื่อความมั่นใจต่ำ |
| GPU 6 GB ไม่พอ | เทรนไม่ได้ | AMP, ลด batch, หรือใช้ EfficientNet-B0/ResNet18 แทน |
| Preprocessing ในแอปไม่ตรงกับตอนเทรน | ผลในแอปแย่กว่าใน notebook | ใช้ฟังก์ชัน preprocessing เดียวกัน อ่านจาก `model_meta.json` |
